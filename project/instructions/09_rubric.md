# Project Rubric

## Project Rubric

### Red Team Charter & Reconnaissance

| Criteria | Submission Requirements | Reviewer Tip |
| -------- | ----------------------- | ------------ |
| Document the scope and objectives of the red team engagement. | The Red Team Charter includes all of the following: engagement details (name, date, assessor role). Objectives listing all 5 attack vectors to be tested (FGSM evasion, data poisoning, prompt injection, data exfiltration, supply chain analysis). A clearly defined scope section distinguishing in-scope systems (receipt classifier, RAG chatbot, deployment infrastructure) from out-of-scope items. Rules of engagement specifying ethical constraints and testing boundaries. Success criteria with measurable goals for each attack vector. | **Fail the requirement if** the charter is not submitted or is a blank template. **Pass the requirement if** all 5 attack vectors are listed as objectives, even if descriptions are brief. **Fail the requirement if** the scope section is missing or does not distinguish in-scope from out-of-scope. **Pass the requirement with comment if** rules of engagement are present but generic (e.g., "follow ethical guidelines") without project-specific constraints. Suggest adding constraints such as "testing in isolated environment only" or "no modifications to production checkpoints." **Praise the learner's work if** the charter reads as a professional engagement document that could be presented to a CISO. |

### Classifier Adversarial Attacks

| Criteria | Submission Requirements | Reviewer Tip |
| -------- | ----------------------- | ------------ |
| Implement a white-box FGSM evasion attack against the receipt classifier. | The `01_fgsm_evasion.py` script implements the `fgsm_attack()` function using the correct FGSM formula: `x_adv = x + epsilon * sign(gradient)`. The perturbed image is clamped to the valid pixel range [0, 1]. The `evaluate_fgsm()` function computes gradients with respect to the input image by setting `requires_grad = True` on the input tensor and backpropagating the loss. The script sweeps across at least 3 different epsilon values. The output demonstrates that adversarial accuracy decreases as epsilon increases. Results are saved to a JSON file. | **Fail the requirement if** the FGSM formula is incorrect (e.g., subtracting instead of adding the perturbation, or not using the sign function). **Fail the requirement if** gradients are computed with respect to model weights rather than the input image. **Pass the requirement if** the clamping is applied after the perturbation and the value range is [0, 1] (matching the ToTensor() output range). **Fail the requirement if** fewer than 3 epsilon values are tested. **Pass the requirement with comment if** the epsilon values tested do not include both small (≤0.01) and large (≥0.1) values. Suggest a wider range for more informative results. **Praise the learner's work if** the attack success rate metric correctly counts only samples that flip from correct to incorrect (excluding samples already misclassified on clean inputs). |
| Implement a label-flip data poisoning attack and measure its impact on model performance. | The `02_label_flip_poisoning.py` script creates a poisoned copy of the training dataset by flipping labels (moving images between class folders). The flip rate is ≤10% of training labels. Only training labels are modified — the test set remains clean. The poisoned model is trained using the provided `train.py` with the poisoned dataset. Documentation includes before/after comparison showing: accuracy, precision, recall, and F1 score for both clean and poisoned models evaluated on the same clean test set. The accuracy drop is at least 5 percentage points. | **Fail the requirement if** the poisoning script does not actually move or copy files between class folders (i.e., labels are not effectively flipped). **Fail the requirement if** the test set is also poisoned — this would invalidate the comparison. **Pass the requirement if** the flip rate is between 1% and 10%, inclusive. **Fail the requirement if** the accuracy drop is less than 5 percentage points. If so, advise the student to increase the flip rate (e.g., from 5% to 8-10%) and retrain. **Pass the requirement with comment if** confusion matrices are not included. Suggest adding them as they clearly show class-level impact. **Praise the learner's work if** the documentation includes analysis of why one class is more affected than the other. |

### RAG Chatbot Attacks

| Criteria | Submission Requirements | Reviewer Tip |
| -------- | ----------------------- | ------------ |
| Execute prompt injection attacks against the RAG chatbot using multiple techniques. | The `03_prompt_injection.py` script contains at least 5 distinct prompt injection techniques (e.g., system prompt extraction, role hijacking, instruction override, encoding bypass, context manipulation). Each technique uses a different attack strategy — not just rephrased versions of the same approach. The script sends each prompt to the chatbot API and records the full response. A transcript document is provided showing: the exact prompt used, the chatbot's response, and a brief analysis of whether the injection succeeded and why. | **Fail the requirement if** fewer than 5 injection prompts are submitted. **Fail the requirement if** multiple prompts use essentially the same technique with minor rewording. Each should represent a genuinely different attack strategy. **Pass the requirement if** not all injections succeed — the analysis of failed attempts is equally valuable. **Fail the requirement if** no transcript or analysis is provided, even if the script runs correctly. **Pass the requirement with comment if** the analysis is present but superficial (e.g., "it worked" / "it didn't work" without explaining why). Suggest the student discuss what the LLM's defense mechanism was. **Praise the learner's work if** the student demonstrates creative injection techniques beyond the standard "ignore previous instructions" approach. |
| Demonstrate data exfiltration from the RAG vector store by retrieving confidential documents. | The `04_data_exfiltration.py` script contains at least 5 distinct exfiltration queries using different strategies (e.g., direct request, semantic proximity, indirect framing, broad retrieval, keyword targeting). The script checks responses for indicators of leaked confidential data and records whether the confidential source document was retrieved. Evidence documentation shows that confidential information was retrieved — either through leaked data in the answer text or through the CONFIDENTIAL document appearing in the sources metadata. The documentation includes a root cause analysis explaining why the vulnerability exists at the architectural level (FAISS has no access control). | **Pass the requirement if** the student demonstrates that the CONFIDENTIAL document appears in the sources field, even if the LLM refuses to share the content in its answer. The retrieval-level vulnerability is the core finding. **Fail the requirement if** fewer than 5 exfiltration queries are submitted. **Fail the requirement if** no evidence of leaked data or confidential source retrieval is documented. **Pass the requirement with comment if** root cause analysis is missing or only mentions prompt-level issues without discussing the architectural vulnerability (lack of access control in the vector store). **Praise the learner's work if** the student proposes specific remediation at multiple levels: immediate (remove document), short-term (metadata filtering), long-term (RBAC in the RAG pipeline). |

### Supply Chain Analysis

| Criteria | Submission Requirements | Reviewer Tip |
| -------- | ----------------------- | ------------ |
| Analyze supply chain vulnerabilities by parsing the Trivy report and reviewing the Dockerfile. | The `05_supply_chain_analysis.py` script parses the Trivy JSON report and extracts vulnerability counts by severity (CRITICAL, HIGH, MEDIUM, LOW). The script identifies specific HIGH severity CVEs with their affected packages and available fixes. The script analyzes the Dockerfile and identifies at least 3 security issues (e.g., running as root, unpinned base image, COPY ., no HEALTHCHECK, build tools in production). Each Dockerfile issue includes a specific remediation recommendation. The supply chain documentation categorizes findings and presents a prioritized remediation plan. | **Fail the requirement if** the script does not parse the Trivy JSON correctly or reports zero vulnerabilities (the report contains 804). **Fail the requirement if** the Dockerfile analysis identifies fewer than 3 issues. The provided Dockerfile has at least 5 identifiable issues. **Pass the requirement if** the student correctly identifies that the container runs as root (the most critical Dockerfile issue). **Pass the requirement with comment if** remediation recommendations are generic (e.g., "fix the vulnerability"). Suggest specific actions like "add `USER nonroot` directive" or "use multi-stage build." **Praise the learner's work if** the student discusses AI-specific supply chain risks such as model integrity through `COPY .`, dependency confusion attacks, or the implications of root access for a container running an LLM-connected application. |

### Results Comparison & Analysis

| Criteria | Submission Requirements | Reviewer Tip |
| -------- | ----------------------- | ------------ |
| Compare and analyze results across attack conditions with quantitative evidence. | The FGSM results document includes a table comparing adversarial accuracy across at least 3 epsilon values, showing progressive degradation. The poisoning results document includes a side-by-side comparison of clean vs. poisoned model metrics: accuracy, precision, recall, and F1 score. Confusion matrices are provided for both clean and poisoned models. The student provides written analysis interpreting the results — not just raw numbers. | **Fail the requirement if** no comparison tables or metrics are provided. **Fail the requirement if** only accuracy is reported without precision, recall, or F1. These additional metrics reveal class-level impact that accuracy alone masks. **Pass the requirement if** confusion matrices are presented in any clear format (table, matrix notation, or text). **Pass the requirement with comment if** the analysis section merely restates the numbers without interpretation. Suggest the student explain *why* the poisoned model shows asymmetric class impact, or *why* FGSM accuracy plateaus at high epsilon values. **Praise the learner's work if** the student connects findings across attacks (e.g., discussing how a poisoned model might be more or less vulnerable to FGSM). |

### Code Quality

| Criteria | Submission Requirements | Reviewer Tip |
| -------- | ----------------------- | ------------ |
| Write attack scripts that are functional, readable, and reproducible. | All 5 attack scripts (`01_fgsm_evasion.py` through `05_supply_chain_analysis.py`) execute without errors when run with the provided infrastructure code. Each script produces output (printed results and/or saved JSON files) demonstrating its findings. Scripts use the provided argument parsing and can be run with default arguments. | **Fail the requirement if** any script throws an unhandled exception when run with default arguments and the infrastructure is set up correctly. **Pass the requirement if** all scripts run and produce meaningful output. Minor warnings (e.g., deprecation warnings) are acceptable. **Pass the requirement with comment if** output is produced but not saved to a file. Suggest adding JSON output for reproducibility. **Do not fail this requirement** for code style issues alone (naming conventions, comments, formatting). These are good to have but not critical for an offensive security project. Suggest improvements in comments if applicable. |

### Suggestions To Make Your Project Stand Out

- Implement a targeted FGSM variant that pushes misclassification toward a specific class, and compare its effectiveness to the untargeted version.
- Experiment with multiple poisoning rates (e.g., 2%, 5%, 10%, 15%) and plot the accuracy degradation curve to find the minimum effective poisoning rate.
- Design a multi-turn prompt injection that builds context across multiple queries before attempting the exploit.
- Propose and implement a simple defense for one of the attacks (e.g., input preprocessing for FGSM, metadata filtering for RAG exfiltration) and measure how it reduces attack effectiveness.
